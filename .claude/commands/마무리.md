## STEP 1 — 변경 파일 수집

`git diff --name-only HEAD` 와 `git status --short` 를 실행해 변경된 파일 목록을 가져옵니다.
`.ts` / `.tsx` 파일만 대상으로 합니다.

---

## STEP 2 — FSD 체크

각 파일을 읽고 아래 기준으로 위반 여부를 검사합니다.

### Import 방향

레이어 계층: `app → pages → widgets → features → entities → shared`

- 하위 레이어가 상위 레이어를 import하지 않는가?
  - `shared` → entities/features/widgets/pages/app 금지
  - `entities` → features/widgets/pages/app 금지
  - `features` → widgets/pages/app 금지
  - `widgets` → pages/app 금지
- 같은 레이어 간 직접 import가 없는가? (shared 제외)
  - `entities/A` → `entities/B` 금지
  - `features/A` → `features/B` 금지
  - `widgets/A` → `widgets/B` 금지

### Public API

- 다른 슬라이스의 내부 경로를 직접 import하지 않는가?
  - ❌ `@entities/company/api/dtos` → ✅ `@entities/company`
  - ❌ `@features/register-company/hooks/use-register-company` → ✅ `@features/register-company`
  - 같은 슬라이스 내부(`../model/types` 등)는 허용

### shadcn/ui import

- 비즈니스 코드에서 `@/components/ui/*` 를 직접 import하지 않는가?
  - ✅ `@shared/ui/*` 래퍼를 통해 사용해야 함
  - `shared/ui/` 하위 래퍼 파일 내부는 예외

---

## STEP 3 — 네이밍 컨벤션 체크

### 파일명
- React 컴포넌트: `PascalCase.tsx` (예: `CompanyTable.tsx`)
- 커스텀 훅: `camelCase.ts`, `use` 접두사 (예: `useSelectCompany.ts`, `use-register-company.ts`)
- 타입·매퍼·컬럼: `camelCase.ts` (예: `types.ts`, `mapper.ts`, `columns.ts`)
- 공개 진입점: `index.ts`

### 코드 내 네이밍
- React 컴포넌트 export: `PascalCase`
- 커스텀 훅 export: `use` 접두사 camelCase
- 타입·인터페이스: `PascalCase`
- 전역 상수: `UPPER_SNAKE_CASE`
- 일반 변수·함수: `camelCase`

---

## STEP 4 — 결과 보고

파일별 결과를 출력합니다.

```
📁 파일 경로
  ✅ 이상 없음
  ❌ [위반 유형] 구체적인 문제 내용
```

위반이 하나도 없으면 "✅ 모든 파일이 FSD 원칙과 네이밍 컨벤션을 준수합니다." 를 출력합니다.

---

## STEP 5 — 사용자 최종 확인

체크 결과를 보고한 뒤, 사용자에게 다음을 물어봅니다.

> 커밋 메시지를 입력해주세요. (입력하면 커밋 + 푸시를 진행합니다. 취소하려면 "취소" 입력)

---

## STEP 6 — 커밋 & 푸시 (사용자가 확인한 경우)

1. `git add` 로 변경된 파일을 스테이징합니다. (민감 파일 `.env` 등은 제외)
2. 사용자가 입력한 메시지로 커밋합니다. (Co-Authored-By 트레일러 포함)
3. 현재 브랜치로 `git push origin <브랜치명>` 을 실행합니다.
4. 성공 여부와 푸시된 브랜치·커밋 해시를 출력합니다.

사용자가 "취소"를 입력하면 커밋·푸시 없이 종료합니다.
